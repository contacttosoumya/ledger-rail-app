Why this prevents price mismatches

Every event references the catalog item by ID, not by a copied price. If you ever update an item's base price in the catalog, every event using it reflects the new price automatically — nothing gets frozen at an old, possibly wrong number. The only way one event pays differently than another for the same item is the explicit discount you set right here, which always shows next to the base price so it's never hidden or accidental.

Menu Access per Person

Grant or revoke View, Edit, and Delete for one specific person on any menu, on top of what their role normally allows

Pick a person below. Each menu has three independent controls — View, Edit, and Delete — each defaulting to whatever their role (shown next to their name) normally grants. Set any one of them to Grant or Deny to override just that action for just that person. Choose Default to remove the override for that action. Granting View alone only lets someone look — grant Edit and/or Delete too if they should actually be able to add, change, or remove entries.

Backups

Status of the daily database backup — run automatically outside this app via the operating system's scheduler

This app doesn't trigger backups itself — a backup that only runs while the app happens to be open isn't a real backup. npm run db:backup mirrors the primary database into a second, independent database, and should be scheduled to run once a day via cron (or Task Scheduler on Windows). See the README for the one-time setup command. Each run below reflects an actual backup attempt, whether it succeeded or failed.
